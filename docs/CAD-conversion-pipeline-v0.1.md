# 多中心 CAD 转化 Pipeline 与质量门控 v0.1

日期：2026-10-20。状态：设计规范，尚未实现完整通用流水线。现有 SH16 v1.2.1-junction-fix 保持不变。

## 1. 目标与边界

面向约 100 个中心，按中心、架构系统、图纸族、图纸修订建立隔离任务。共享基础语义、图样变体与验证规则，保留项目差异。每次运行生成可追溯节点边数据、源 CAD 对照、问题清单及带门控状态的可视化包。

不能承诺自动发现所有 CAD 错误。目标是通过源数据覆盖、独立拓扑检查、异常集中复核和门控自身测试，让漏识别及错误排除更容易暴露，并禁止已发现的问题静默通过。

SH16 的数量、楼层、坐标、块名、两系统配置不得成为其他中心的通用默认。新架构需要声明供回水、一次二次侧、冷却水等实际系统及设备端口语义；不假定全图只有一个连通分量。

## 2. 四类版本，分别管理

1. engine_version：解析、几何、图构建与校验代码。
2. symbol_library_version：设备语义、端口模型、已验证图样及负样本。
3. family_profile_version：设计院/制图标准、图层、图例、省略画法、旋转镜像约束。
4. project_config_version：中心、架构、图纸修订、单位、系统、范围和已确认例外。

run_id 唯一标识一次运行；输入 DWG/DXF、外部参照、代码、配置和规则全部记录哈希。同样输入与版本应可重复生成同样的语义结果；跨修订通过来源锚点与匹配表维护 ID，并显式报告新增、删除、拆边和合边。

## 3. 流程与逐阶段产物

| 阶段 | 处理 | 必须保留的产物 |
|---|---|---|
| S0 接收与冻结 | 收齐主图、图例、接管详图、参照及修订信息；保存原文件 | input_manifest、缺件/外部参照清单、文件哈希 |
| S1 原始实体盘点 | 独立列举布局、实体、递归 INSERT、单位、图层、颜色、曲线、文字及解析失败 | source_entities、展开实例路径、parse_issues |
| S2 图样与系统适配 | 本图图例优先；匹配项目、图纸族、基础库；识别未知与候选冲突 | symbol_candidates、recognition_decisions、project_profile |
| S3 几何规范化 | 分系统处理误差、已验证展示腿、软接、跨越断口；保留原几何 | geometry_actions、segment_lineage、待确认几何 |
| S4 图构建 | 更新节点、端口、相邻边；补通后重检三向连接；恢复有证据的边界接口 | nodes、ports、edges、edge_source_spans |
| S5 部件归属与语义 | 部件按实例归边；检查设备端口、系统隔离、源管路覆盖 | instances、inventory、port_bindings、coverage |
| S6 独立质量检查 | 从源图验证图、从图回查源图，计算所有门控 | quality_report、issues、exclusions、review_queue |
| S7 人工复核与修订 | 处理新图样、影响连通性的问题及抽样；留存证据与结论 | review_decisions、人工例外、局部对照图 |
| S8 分状态打包 | 生成英文可视化、节点边、审计与问题列表；满足发布条件才进入 release | inspection 包或 release 包、manifest、校验和 |

每阶段显式给出输入数、输出数、状态、耗时与错误。依赖项不满足时，下游可生成诊断材料，但不能伪装成有效最终结果。批处理可以继续处理其他中心，不因一张图失败而吞掉该图失败状态。

## 4. 防止静默跳过：三本账

### 4.1 原始实体去向账

先用独立盘点器列出所有源实体，而不是在识别器返回结果后再统计。递归展开对象需用顶层句柄、INSERT 实例路径和子实体键区分，不能仅用块定义句柄。

每个对象有唯一主处置：用于管路、用于符号/文字、被规范化替代、明确排除、未解析。对象可另有多种语义引用。每一条过滤、类型不支持和异常捕获都输出记录及 reason_code。未解析对象仍保留在源实体总数中。

盘点账 100% 有去向不代表识别正确；排除与未解析不能计入语义识别成功。另行检查排除是否有证据、未知是否影响范围、排除量是否异常。

### 4.2 管段覆盖账

按源实体上的参数区间建立原子管段，保留系统、端点与原长度；不能只比较总长度。每段必须能追踪到边、源设备内部接管、有依据的展示几何、未解决范围边界或其他显式处置。

原始几何先记账，再裁图或规范化，不能先丢弃再重算分母。合成补通段单独记录，不抵消原始管段的漏覆盖。省略符两侧源路径分别记录；实际断口可为语义连接，不能冒充原始 CAD 连续线。

### 4.3 设备与端口候选账

候选集合由图例、块/炸开几何、文字标签、管端/端口邻域等多路产生，记录候选来源及去重关系。每个候选必须有接受、拒绝或待确认结果，并保留候选模板和拒绝原因。不能仅对识别成功的设备证明全部归边。

独立候选扫描仍可能漏检，因此还需风险抽样和人工局部核图，不能把候选全集当作实际设备真值。

## 5. 质量门控

| 门控 | 判据 | 失败/不确定处理 |
|---|---|---|
| G0 输入可用 | 输入可读、必要图例/参照已收齐或缺失影响已明确、单位可解释 | 影响范围不明则阻断；仅可出诊断包 |
| G1 源对象可追踪 | 盘点账闭合、无无记录过滤、解析错误及不支持类型全部留痕 | 未记账对象阻断；范围内未解析对象进入影响评估 |
| G2 图样与端口 | 用到的类型有来源和语义；新增/冲突图样完成确认；未知形状不强制最近匹配 | 影响设备类型、端口或连通性则阻断发布 |
| G3 几何操作 | 每次删、裁、合、补都有前后几何及证据；系统和单位合法 | 证据不足不自动补；有争议的操作待核查 |
| G4 源管路覆盖 | 所有范围内源管段区间有合法去向；无重复归属或遗漏而不解释 | 漏段、误排除及无归属原子区间阻断发布 |
| G5 拓扑与端口 | 三向真实连接有节点；边不穿过第三节点；端口匹配；跨越不误连；系统不串接 | 缺节点、缺边、悬空端口、非法跨系统连接阻断发布 |
| G6 资产清单 | 已识别实例恰当归属；实例/聚合/端口/图一致；对照可独立获得的设备台账 | 数量或名称不一致阻断；没有独立台账需明确验证边界 |
| G7 差异与复核 | 新规则影响已知案例不退化；新增/删除/拆合边变化有解释；高风险项已复核 | 未解释的关键变化阻断；抽样不能替代已发现问题的处理 |
| G8 交付一致 | CSV、JSON、viewer、清单及输入哈希一致；离线启动通过；状态无失真 | 数据不一致或掩盖未决项阻断发布 |

三向判断按真实几何连接语义执行，不要求轴测投影中存在对向共线。跨越内部不建节点，但补通后沿路径形成的真实三向端点必须重新识别。每轮规范化后重检受影响区域；有新增节点则重新拆边与归属。过程收敛或达到配置上限，未收敛为阻断，不无限重试。

T 节点通常度为 3，但必须结合端口语义区分真实异常、双系统共址、多端口设备和源图不确定性。连通分量只与项目声明的系统/分区及源证据比较，不强制全图连成一片。

范围外排除不能只凭画框坐标。检查被裁断线头是否连接图内系统、是否存在省略符/设备接口；有连接证据的候选必须复核。纯图例/详图排除要留图层、位置、结构和与主管隔离的依据。

## 6. 独立校验与门控自测

生成器不可自行写入 true 充当证明；质量指标由校验器读取实际文件重新计算。校验器可以共享源读取格式，不应直接复用被验证的 T 检测函数作为唯一判定依据。

至少具备：源三向候选点与最终节点差集；对每条边检查内部是否跨过第三节点；边与源原子管段双向覆盖；端口/标签台账对照；疑似断口、孤岛、近邻错接、遗漏接口及异常排除检测。

用已知问题图与故障注入验证门控，而不只验证生成器能成功：删除节点、删除边、保留数量但改接端点、跨系统错接、排除一个真实接口、隐藏未知符号、吞掉 ARC/嵌套块解析错误等，必须触发对应门控。验证定位正确、错误类型正确、退出状态正确；不仅检查程序是否报过一个错误。

SH16 应保留“旧版漏 T303/T305”“C19 错排除”“跨越误连”反例。升级图样或代码后，对受影响图纸族及跨族通用核心回归，不能只测当前新图。

## 7. 问题记录与状态

issue 至少包含：issue_id、center_id、architecture_id、drawing_id、revision、run_id、stage、rule_id/version、severity、status、source_handles/instance_paths、bbox、system、node/edge/port_ids、evidence、建议处置、reviewer、review_time、resolution、waiver。

问题闭环为 open → investigating → resolved 或 accepted_exception。修复后重跑受影响门控，不因填了原因就自动关闭。人工例外限于特定来源哈希、规则、图纸和修订；输入或相关规则变化后需重评。阻断性解析失败、缺源数据、失去追溯等不能通过简单豁免变绿。

门控状态：PASS、FAIL、REVIEW、NOT_EVALUATED、NOT_APPLICABLE。NOT_APPLICABLE 需要条件和证据，例如源盘点证明本图没有该类曲线；未实现或未运行不可写成 NOT_APPLICABLE。

整图运行状态：BLOCKED、NEEDS_REVIEW、READY_WITH_EXCEPTIONS、READY。任何 FAIL 或必需检查未运行不得发布；影响物理拓扑的未决 REVIEW 不得发布。已获允许且可追溯的例外仅能进入 READY_WITH_EXCEPTIONS，不能被计入干净通过率。

检查包可在 BLOCKED/NEEDS_REVIEW 时输出，必须显著显示状态及未决项，并与正式 releases 分开。批处理必须输出成功、待核查、阻断、未运行的中心/图纸列表，不能只展示成功项。

## 8. 人工核查分层

- 新图纸族首张图、新设备图样及端口模型：覆盖全部变体和实际接管样例。
- 所有影响连通性的异常与不确定操作：逐项复核。
- 每次几何规则变化：检查变更前后局部 CAD 对照及受影响图。
- 稳定图样/无告警区域：按系统、楼层、识别方式、复杂度分层抽样；保留抽样总体、方法及区域，避免只选看起来正确的位置。
- 抽样发现漏项：暂停同族未发版结果，扩大复核受影响范围，新增反例后重跑；抽样通过不是零缺陷证明。

不设置统一“匹配率超过 95% 就发布”的门槛；一处错接可能改变整网。置信分数仅用于排序，需以已标注样本校准，不替代硬约束和复核。

## 9. 100 个中心的批处理组织

建议任务路径：centers/<center>/<architecture>/<drawing>/<revision>/runs/<run_id>/，包含 input、profile、source-ledger、normalized、graph、quality、review、inspection、release-manifest。上层全局登记图纸族、版本、状态、影响范围和重跑依赖。

先对 100 个中心做文件/图层/符号/系统/参照的轻量盘点，形成实际图纸族，再选每族代表图和复杂反例试跑。不是预先假定只有若干设计院或按文件名强行分族。

采用受控小批次：先少量代表架构验证端到端，稳定后逐族扩展。批次大小由问题率、复核能力和图纸复杂度决定，不预设全部自动通过。新图样只改项目/图纸族适配；通用规则升级要证明对已通过案例没有未解释退化。

## 10. 建设顺序与现状差距

第一阶段：从 SH16 拆出通用引擎、图纸族 profile、项目配置和案例期望；去掉生产流程中的固定数量及硬编码范围；支持所需架构的系统/端口模型。

第二阶段：优先补源实体去向账、原子管段覆盖、候选识别账、问题登记和统一门控状态；保证 unknown / excluded / unsupported / caught_error 都可见。

第三阶段：建立独立拓扑检查器、故障注入反例与图纸族回归集；保留 SH16 已发现缺陷，而非只更新正确结果的计数。

第四阶段：在 viewer 中实现问题列表、定位源实体、状态、前后对照和复核记录；接入多中心批处理登记、重跑依赖和分状态交付。

现有已具备：SH16 可复现基准、部件归属、部分几何审计、四处新增 T 节点与邻接度验收、viewer 一致性、CAD 对照和交付哈希。

当前缺口：全源实体处置账、完整源管段覆盖、独立未知符号发现、统一问题闭环与发布阻断、跨中心去硬编码、通用多架构适配。现有 viewer 的 source-path coverage 主要验证输出路径字段一致，不等同于源 DXF 全管段覆盖；已识别部件全部归属不等同于全部设备已识别；没有例外审批的 5 个 SH16 待核查点按本新政策应属于检查版，不能追认为零缺陷正式验收。

本规范尚未写入或替换已发布 Skill/应用，后续实现与验收须明确记录版本。
