# SH16 双视图拓扑修复、互证与资产化计划

执行副本。状态以 `skills/orchestrate-cad-drawing-pipeline/assets/sh16-s0-ledger.json` 为准。历史基线不自动代表正确。

## 1. 目标与执行原则

最终交付以 SH16 轴测图为锚点，展示同一系统的连接、设备、管径和长度，并可追溯至平面图及轴测图原始证据。

实施顺序：

**历史能力继承 → 平面图既有问题闭环 → 轴测图自身校验 → 双视图映射 → 双向互证与纠错 → 属性融合 → SH16 验收 → LF20 回测。**

- 平面图拓扑正确是正式映射的前提，上一轮平面图问题全部继续执行。
- 轴测图也须独立检查，不能把它当作免检答案。
- 两种视图描述同一系统，连接关系互为印证；不得用一方未经证明的推断自动修正另一方。
- 历史 feature 和本轮修复具有同等发布阻断效力。
- SH16 为开发和正确性验收主项目；LF20 为规则稳定后的泛化测试集。

## 2. 必须保留的工作与双视图规则

平面图既有问题保持完整范围：原图与元素、几何与连接、设备与端口、边界与立管、元件与属性、主详图与上下文、完整性与交付。

每项状态只允许：`reproduced`、`to_fix`、`fixed_pending_regression`、`source_ambiguity`、`not_applicable`。图数量或边数量一致不能替代正确性检查。

双视图规则：

- 连接互证允许详略不同，通过路径对应表达，不要求节点、边数量相同。
- 管径只在已证明连通的同系统管路内经真实 T 继承。冲突不选边、不填零。
- 水平管段的管径和物理长度来自已匹配楼层平面图。跨层竖管的管径和长度来自轴测图。
- 井区只提供定位范围。井名或位置相近不能单独证明连接。
- 冲突保留两侧证据。修复所属阶段后重算，不能直接改最终融合图。
