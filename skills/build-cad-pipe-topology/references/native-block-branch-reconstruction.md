# Native block branch reconstruction

Use `reconstruct_native_block_branches.py` when an existing axis equipment edge has a selected native INSERT and its source paths stop at an inline symbol or an omission marker while a final segment merely reaches a display anchor. A graph path to a displayed equipment center does not establish a physical pipe.

## Source proof

Pin source, local graph, canonical component inventory, joint definition fingerprint and explicit edge scope. Strict Chinese readability precedes geometry. Independently replay an input confirmed-gap-joint stage when present. Reject already reconstructed graphs and graphs with cross-view attribute fusion: fusion is downstream and must be regenerated.

Reuse `native_device_circle_lines` and `native_nested_joint_evidence` to reproduce the exact selected INSERT/direct-child circle, pipe and six-entity flexible-joint chain. Require one assigned canonical joint instance, a same-system inner pipe reaching a native equipment-layer circle, a uniquely covered outer pipe and a native same-system three-ray T. Preserve native source chains, layers and XYZ. A text caption must be unique; the original logical equipment identity is retained, not newly certified as a physical port or cross-view identity.

`projected_coverage` invokes the existing single-path audit separately on explicit read-only path projections. Each projection gets its own content hash and original path index; never label a modified in-memory projection with the original graph hash. Do not change the legacy coverage module or its historical mapping receipts merely to admit multiple paths.

Require exactly one unsupported terminal display-anchor span; every retained original segment must have one native LINE witness. For a direct branch, trimming that span must leave the native outer joint contact. For a paired omission, require exactly two native open six-vertex, zero-bulge DIM_SYMB markers in the selected INSERT: the displayed anchor is the main marker center, its retained pipe ends on that glyph, and the remote path uniquely links the other glyph to the outer joint contact. A shared untyped marker never joins supply and return. An arbitrary gap, a third marker, competing source witnesses or another unexplained span remains pending.

## Reconstruction and conservation

Retain every witnessed original pipe segment. Remove the unsupported display-anchor span from pipe geometry and keep its complete original edge in source history. Add the actual inner source LINE from the joint to the equipment circle as a separate path. Preserve the inline joint and omission as explicit drawing relationships with unknown physical lengths, not invented zero-length pipes. `path_length`, `drawing_path_length` and `source_path_length` describe only the resulting native LINE paths; installed length stays unknown and incomplete.

Preserve nodes, IDs, systems, floors, original logical equipment association, source INSERT and canonical per-edge component inventory. An affected older block-attachment snapshot moves to history because its path changed; unaffected mappings remain current. The new independently replayed source-chain evidence supersedes that snapshot for source geometry, without inheriting HIL or physical-port approval. Preserve whole original edges and the previous parent graph.

`sourceNativeBlockBranchReconstruction` and each edge's `source_native_block_branch` record the repair and endpoint/path snapshot. Invalidate affected DN, physical length, correspondence, fused attributes and human review. Unsupported selected chains are explicit. Scope/count assertions are project policy checks, not universal expected counts.

## Pipeline and presentation

`pipeline.py validate-native-block-branches --reconstruction-run ...` independently replays the feature and remains pending for downstream work. Source comparison replays this stage before inherited gap-joint flags, then recurses to the real original parent comparison. A later attribute-fusion stage is replayed first and references this local graph. Retain unrelated parent blockers and require affected attributes to be recomputed.

Viewer proof order is attribute fusion → native block reconstruction → equipment ownership/identity where applicable → inventory-only gap joints → prior source repairs. Check current source-chain/path snapshots before permitting equipment navigation. Display native pipe pieces without the removed anchor stroke; source CAD context explains the omission and inline glyphs. Keep unknown physical lengths and old annotations under their old dataset identities.

Replay older confirmed paths on the new local graph only if their reviewed snapshots are unchanged. Regenerate mapping receipts and fused attributes with current hashes; preserve their previous length values and unresolved DN status when the evidence is unchanged. Do not silently copy acceptance from an old dataset.

## Tests and current scope

- `test_reconstruct_native_block_branches.py`: direct/omitted branches, mirrored native INSERTs, projections, source/component/anchor failures, snapshot history and inventory consumption.
- Existing native path coverage, nested joint and device-circle tests remain required.
- Pipeline `test_native_block_branch_gate.py`: dispatch, parent blocker retention, stale source and later-fusion order.
- Viewer `test_native_block_branch_viewer.py`, source guards in `test_calibrated_ownership.mjs`, full builder and inherited cross-view attribute tests.

SH16's initial scoped run reconstructed 32 first-floor edges: 24 omission branches and 8 direct branches, including four inherited offsets. A later explicit scope retained those 32 exactly and added 28 upper-floor branches. The complete upper-floor native INSERT screen then checked all 140 branches under the same rule; rebuilding their union with the initial 32 yields 172 branches. Preserve the earlier selection as a prefix and compare every inherited edge/evidence record exactly, not only totals. This source-path family still does not certify the whole 11 drawing, solve exploded chains or floor-plan topology, select DN, measure omitted pipe or complete LF20/HIL.

## Inherited bounded-offset contacts

When strict center contact fails for an explicitly declared historical scope, pass `--offset-policy` and `--offset-audit` with both file hashes and `offset_edge_ids` in the current policy. Reproduce the original source identity, correction membership, joint definition and audit-policy binding. Re-run `native_offset_circle_candidates` within that existing bound; require exactly the same unique source LINE/CIRCLE geometry and the same native joint/component evidence. The ordinary center case remains strict. Competing circles, changed Z, stale control geometry or another component assignment must fail rather than broadening snapping.

Use the actual LINE endpoint in the reconstructed pipe, not the nearby circle center. Store the original offset as drawing evidence with unknown physical length/port; do not create an extra measured or zero-length pipe. Require every declared offset control to be consumed exactly. Reuse the canonical `_inventory` guard and reject repeated native joint identities across reconstructed edges. Tests cover mirrored offsets, missing/stale controls, competing circles and source inventory mismatch. This extends an inherited feature into a later entry; it is not a new expert decision.

When extending a project scope to another floor, inspect the complete existing offset policy and audit before classifying a repeated contact as a new unsupported family. SH16's original control contains second-floor east supply contacts as well as the first-floor subset. Include only the selected historical memberships and replay each unchanged native control; never copy a first-floor-only selection list as the whole feature scope. Rebuild from the immutable pre-reconstruction parent with the union of old and newly proved edges. Verify old reconstructed edges/evidence exactly, all unrelated edges, node/edge IDs, upstream colour corrections and canonical component bytes. Recompute mappings and fusion against the new local graph hash; old viewers retain their prior identity.

Run a read-only full-family scope inventory before scheduling another small expansion. SH16's original bounded-offset policy contains 16 memberships: 4 first-floor, 6 second-floor and 6 third-floor contacts. The same native rule covered all 140 upper-floor INSERT branches once the applicable existing memberships were supplied. Scope omission must not be reported as an algorithm or CAD defect. Keep a newly rebuilt full-family local candidate separate from an older mapped presentation until its correspondence/attribute dependencies have been replayed; never claim the presentation already uses the candidate.
