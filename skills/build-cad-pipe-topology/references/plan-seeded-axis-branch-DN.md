# 从平面主管管径经轴测真实三通继承到支路水平区段

当两图的一个主管范围已独立对应、主管管径已由平面原图证明，但内部设备表达数量不同，先应用已确认的管径继承规则。区段管径的继承不要求先给每台设备分配跨图身份；连接、来源和作用域仍须分别成立。长度及设备身份不随管径继承。

1. 重新执行原有平面主管范围、构件分区和管径归属的完整 owner；核对当前查看器实际采用的主管记录逐字节一致。不能借旧图的 DN 缓存或轴测水平文字作最终种子。
2. 在当前图中批量筛查主管真实三通的第三臂。两个主管臂须在该接点各有同一系统、楼层、来源范围及同值管径的水平作用域。原 CAD 三射线须证明它们是唯一的一对反向贯通臂，支路不得反向给主管赋值。
3. 用原始 `native_drawing_marker_ports` 和 `inherited_marker_and_crossover_evidence` 读取完整接口及两个独立供回水端口。30绘图单位仅是既有非物理省略标记的定位容差，不能用于管道接点吸附。圆心显示短线不属于物理管道。
4. 完整复查从三通到源接口的每一段，重用原生 LINE、XYZ 接触和两臂弯头检查，保留自动排气阀显示支腿归一化。当前入口仅接受连续、唯一原生 LINE 支路；需要断口／交叉修复或归一化三通的候选明确保留，不能造一段 LINE 让它通过。
5. 对完整物理支路重跑原始管径归属、复合文字、嵌套文字和 F 标注屏障。轴测文字只用于一致性检查；变化或未解决的标注必须停止继承，不能将主管管径写到推测的变径点前。保护每个已有已知值。
6. 只输出已核对的水平区段管径与完整证据链。竖直管径仍取11图，未知长度保持空值，设备个体映射保持原状态。独立重放通过后才可接入新查看器；源结果、查看器采用、实际导出和人工验收分别记录。

入口：

- `pipeline.py reconstruct-plan-seeded-axis-branch-DN --manifest ... --output ...`
- `pipeline.py validate-plan-seeded-axis-branch-DN --verify-output ...`

固定输入包括原有 uniform/received 主管证明、原始轴测 CAD 与图、原分段方向记录、当前查看器 manifest/provider/effective 和原始元件清单。依赖内容或实现哈希变化须重新运行。`test_plan_seeded_axis_branch_DN.py` 包含真实 DXF 三通与省略标记、旋转镜像、供回水独立、缺少主管臂、作用域／楼层变化、下游变径、额外射线、Z 错位、未知方向、旧值冲突和中文损坏反例。

SH16 是开发样本；LF20 只在 SH16 规则稳定后做回测。源资格筛查通过不能冒充完整双项目重建、整边属性齐全或人工确认。
