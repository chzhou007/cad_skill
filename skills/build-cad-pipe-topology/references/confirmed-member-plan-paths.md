# Confirmed pipe members: detail topology, plan route extent

Apply this only after an explicit compound-lane meaning and original main/detail
aliases have been replayed. A coincident source LINE can carry two physical
pipes. A detail branch belongs only to its confirmed member; do not duplicate
every T or inline component into both networks. Ordinary crossings remain
outside this convention. Repeated labels are not physical pipe counts.

`confirmed_member_plan_paths.py --manifest MANIFEST --output NEW` replays the
current local topology owner, original compound reply, detail owners/T rays,
archived wave directions and native source LINE hits for the whole paired
cohort. Both services stay independent. Every adjacent canonical main must
already have exactly one edge, and its two projected anchors must lie on one
unique continuous native carrier inside a dimension-corroborated mm plan
window. Source TEXT alignment and extent must match that carrier. Split,
omitted or competing carriers need their own reader, not a wider tolerance.
Validate independently with `validate-confirmed-member-plan-paths --member-run`.

This recovers a separate plan coordinate domain for the existing detail T
network. It does not move or reconnect the canonical graph. Existing Ts and
edges are already correct inside the accepted cohorts; source path and metric
evidence are what was missing. Unknown group-end connections stay unknown.

Record **T-to-T run centreline**, including any inline assembly extents, separately
from net pipe cut length and whole installed pipe length. Native plan units and
two independently oriented dimensions are required. Neither an axis drawing
span nor a detail drawing span supplies this quantity. Never scale detail valve
stations into plan coordinates, subtract unknown body sizes, count circle radii,
or assign an omitted branch connector length. Preserve every component on its
existing edge; projected component-to-member allocation may remain unresolved.

`confirmed_member_plan_attribute_context.py` binds these fresh native paths to
an unchanged, qualified axis artifact's existing one-to-one, same-floor T-to-T
correspondence. Require the exact plan graph/source, current known DN agreement,
axis horizontal domain, rendered geometry and input hashes. No new mapping is
accepted by this adapter. Group allocations, mixed/vertical paths and conflicts
remain pending. The source-bound effective context is part of the new HIL
identity; original canonical graphs and old annotations remain historical.

`refresh_confirmed_member_attributes.py` is a new versioned owner. It retains
the original `refresh_attribute_templates.py` byte-for-byte for old releases.
It independently replays member evidence, retains the complete qualified CAD
rendering, exposes the run's DN/source/length in properties and CSV, and runs
actual native schema/fidelity checks. Its artifact-only reuse does not claim
fresh reconstruction of every historical mapping. Use
`validate-confirmed-member-attribute-refresh --bundle` for independent replay;
then inspect the actual browser and exported CSV. Technical replay is not HIL.

Required negatives: wrong member/service/floor, changed reply or source, missing
canonical adjacency, a duplicate source LINE, a label outside the cohort, mixed
or grouped axis extents, stale rendered geometry and attempted net-pipe-length
promotion. Preserve the legacy wave, inline, Chinese, F-label, ordinary-crossing,
old attribute and review-invalidation tests in the same registry.
