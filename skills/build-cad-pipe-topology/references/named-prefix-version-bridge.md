# Retain named upper-floor scopes after a paired-wave reconstruction

Use `native_named_prefix_version_bridge.py` when the four already checked named
riser approach/network-link scopes still refer to the exact parent of a new
`inherited_wave_pair_continuity` local reconstruction. Reuse the historical
named-segment, current wave, native T/through-role, DN, named-label and plan XY
owners. This mode does not establish another pipe correspondence.

```
python native_named_prefix_version_bridge.py --historical-attributes-run OLD_SCOPES --current-plan-run CURRENT_WAVE --output NEW_EVIDENCE
python pipeline.py validate-named-prefix-version-bridge --bridge-run NEW_EVIDENCE
```

Both native parent ancestries must independently replay. The current wave
parent must be the exact historical scope local graph and source. Require
unchanged selected edges/nodes, both equipment service traces, all four true T
roles, native riser annotation domains, every DN inheritance chain and every
length piece/source LINE. Unknown or different values require reconstruction
of the affected stage. An equal numeric total does not establish preservation.

Output is separate source/version evidence. It preserves original IDs and
receipts, leaves mappings and graphs untouched and never inherits HIL. A
successful pipeline check returns pending/exit2 until the current evidence is
adopted into the complete graph, source comparison and viewer. Do not rewrite
old graph hashes or cast a read-only preflight into native parent acceptance.

Run `test_native_named_prefix_version_bridge.py`,
`test_named_prefix_version_bridge_gate.py` and historical named upper-floor,
paired-wave, touching-path and unit/DN regression. Full native execution and
independent owner replay are separate from these unit tests.
