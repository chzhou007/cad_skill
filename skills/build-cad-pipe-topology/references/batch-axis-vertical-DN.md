# Apply native DN readers to every vertical segment

Use `axis_vertical_DN_batch.py` after the independent native direction-routing
artifact. Keep original edge, path and segment IDs. A multi-path graph edge is
projected into private, single-segment reading domains; these cuts are not
physical nodes and never replace the local topology.

Reuse the original modelspace segment-DN reader. A selected nested root is not
a modelspace LINE: route those observations to the existing repeated native
branch-layout owner and then its original segment-domain locator. Retain exact
root/child chains, text profile, pose, source Z, graph ownership and at least
four independent source controls. Targets never train themselves. Do not lower
that threshold to force a small family through.

Apply complete families in process batches. A failed native target is retained
and the other independent targets are still checked. A successful sibling is
not used as learned evidence: the original owner independently re-reads its
control corpus each time. Source changes invalidate the batch.

F-owned text stays with the ordered F reader. Unparsed, ambiguous and competing
DN annotations remain scope barriers. Conflicting values on one original
segment require transition extents; do not select the more frequent value.

Publish only `native_axis_vertical_annotation_segment_DN` domains with native
witnesses and annotation lineage. Keep horizontal floor-plan values, prior
vertical values, graph topology, component identities and all old annotations.
The versioned viewer refresh appends vertical-domain fields to actual UI/CSV;
it never writes a whole-edge DN or physical length. Related HIL is invalidated.

Use `validate-axis-vertical-DN-batch` and
`validate-axis-vertical-DN-attribute-refresh`, source-CAD wide/local pairs and
actual browser/CSV checks before publishing. Technical source attribution and
human acceptance remain separate. Low-control families, source ambiguity and
unannotated spans stay in technical queues before new HIL questions.
