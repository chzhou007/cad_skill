# Attach axis segment DN beside existing plan attributes

Use `attach_axis_riser_segment_attributes.py` after the native vertical DN scope
entry. Replay both that scope and the full refined plan-attribute parent before
attaching values. Keep the immutable local axis graph, every prior plan value,
all nodes and the canonical component CSV. Changing any of them invalidates the
dependent attachment and review state.

Store `axis_riser_attributes` separately on each original edge. Every record
names its original path/segment, exact native endpoints, floor pair, service,
source LINE, scope/source/graph hashes and direct or T-inherited DN lineage.
The current segment must still equal the scope and original local graph. The
whole mixed-edge DN and length remain unknown; no value is assigned to its
horizontal approach and no synthetic physical node or pipe is created.

The `sourceAxisRiserSegmentAttributes` root indexes exactly those records.
`source_comparison_gate.check_axis_riser_attribute_graph` dispatches before the
refined parent and independently reproduces the attachment. Carry every exact
parent error and unresolved scope; a new successful segment check does not
clear old defects or inherit human acceptance.

The viewer replays the new owner stage once. It then reuses only the parent
attribute context reproduced during that same replay, with exact file hashes
and common ancestor checks, rather than repeating the entire parent replay.
This is not a persisted trust flag or a general verification cache. Use the
same native source document in final schema validation. The edge records must
match the root, unique current segment and native same-system covering LINE.

Display the vertical DN with its floor/segment limits and source 11 evidence.
The horizontal domain continues to use mapped floor plans. CSV puts the segment
values in separate columns and retains unknown physical lengths as blanks.
Ordinary plan-only and legacy edges retain their existing values and behaviour.
The frontend and Python validator reject stale placement, a wrong service or
floor, duplicate scopes, changed evidence and numerical whole-edge claims.

The latest expert clarification selects SH16 11 itself as the source for
cross-floor vertical DN and length; SH16 08--10 remain floor plans. This source
selection does not confirm the meaning or datum of parenthesized numbers such
as DN200(2.900) or DN300(3.200). Preserve those as source text until their meaning
and pipe endpoint scope are independently established. Do not derive a vertical
physical length merely from floor elevations, plan XY lengths, or those numbers.

Run the registered attachment, source-gate, viewer ancestry, native validation
and JS property/export tests together with historical plan DN, source ancestry,
component, source rendering and builder regressions. Full native composition,
source comparison, generated viewer, live UI/export and expert acceptance remain
separate checkpoints. Observe an existing long replay by its live process;
an observation timeout does not authorize restarting it.
