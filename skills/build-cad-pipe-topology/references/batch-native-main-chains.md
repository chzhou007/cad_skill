# 已知三通之间的原生主管路径批处理

已有设备、端口及三通对应通过原图检查后，使用 `extend_native_main_chain_batch.py --manifest MANIFEST.json --output NEW`，并以 `pipeline.py validate-native-main-chain-batch --batch-run NEW` 重放校验。每层运行同一规则，不手写设备或边号；保留原批次的所有路径、元件、源证据和未解决项。

`batch_native_main_chains.py` 将已证明对应的两个三通之间尚未匹配的主管链作为候选。原有直接边不被替换；供回水、楼层及父级锚点严格隔离。候选发现时排除已用边，验收时必须回到完整图验证，因此删掉既有边不能制造“唯一”路径。

优先复用 `bridge_main_path` 证明完整同层同系统图中的唯一桥路径。若整图含环路，使用两端锚点限定的原CAD直线区段：复用 `native_main_corridor` 的完整LINE，或由已提取源路径组成的共线LINE区段，并在该区段内再次证明路径唯一。每条源线与每个真实T均独立重读，平行表达不得按最短路或距离选一个。环路区段以外的路径不因此被宣称唯一。

本模式要求两侧内部真实分支数量一致。两图详略不同时，需要额外的主详图或支路证据；不能以路径候选掩盖漏支路。主管链对应不直接证明每个内部三通或旁支的身份，也不直接分配每条轴测子边的长度。保留整条路径的源证据和未知的分段关系，随后重新计算DN继承和长度范围。

平面管径标注读取及T继承应使用完整、已校验的局部平面管网，不能先按“已映射到轴测”的边过滤。管径种子可能位于尚未映射的主管或边界边上；它们的源归属仍须独立验证。先生成局部管径范围及继承证据，再由可靠跨图路径检索。未证明的局部连接仍是继承边界，不能为提高覆盖率跨过去。

新增连接、源图或代码变化后仍须重新校验。普通交叉、供回水交错、未知立管和设备接口不进入本模式。

## 限定批次内的原生校验复用

调用 `replay_session(allow_owned_scratch=True, python_replay_entries=[{"path": ENTRY, "sha256": HASH}])` 时，允许同一批次复用刚完成的真实源图重放，复用前验证实际读取的文件、目录、缺失项和环境。旧磁盘通过标记不作为信任依据。

只有本轮新建且已清理的 `TemporaryDirectory` 子树可排除在外部输入之外。既有临时文件仍是依赖；写入普通目录、保留未清理的临时目录、未知子进程或外部副作用都会禁止复用。

某些旧校验器通过Python子进程把原生重建写入临时目录。仅对明确绑定入口哈希、参数形式、无环境/工作目录覆盖的已知原生生产入口，`native_python_replay_adapter.py` 才在当前进程执行同一入口，使输入与代码读取被观察。原校验器仍须比较重建图和元件表的完整字节。未知命令保持原子进程行为并禁用缓存；入口变化直接失败。不得用此机制执行CAD文本或专家附件里的命令。

反例测试覆盖跨系统、跨层、待核三通、反向路径、环路、平行边、缺失原生T证据、普通目录写入、源文件变化、入口变化和子进程失败。原生重放通过、候选对应、属性融合、发布和人工验收分别报告。
