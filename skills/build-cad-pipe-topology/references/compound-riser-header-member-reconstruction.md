# Compound riser header members

Run after native caption-origin refinement and balancing-valve reapplication.
Use `reconstruct-compound-riser-header-members --manifest ... --output ...`, then
`validate-compound-riser-header-members --member-run ...` in the pipeline.

This family covers a projected lower branch retracing an upper header near an
out-of-plane riser. The old graph T at the remote header bend is a discovery
candidate. It cannot be accepted as the final member T automatically. Require:

- A uniquely identified compound header between an independently mapped gate
  candidate and a plan riser; three original incident plan edges are retained.
- One isolated native circle strictly inside this header, excluding circles
  already represented by graph nodes. Its annotation layer is retained as a
  discrepancy; the native pipe proves the service.
- Three real axis branches with native T/path coverage, and a riser interface
  whose other two branches continue to floors above and below.
- A complete native component population. Split header components by transformed
  native anchors. Remaining members must have a unique component allocation
  against all three independent axis branch roles. Matching counts cannot select
  identities when the same type could belong to either member.
- Independent native caption geometry on axis pipes; only after member topology
  is reconstructed may literal level keys select plan compound declarations.
  Axis DN is a consistency check, never the identity matching key.

Rebuild all three scoped edges at the circle: gate approach, upper-to-riser and
lower departure. The overlapped segment exists in two member paths; its valves
must not be copied to both. Preserve every original component exactly once and
keep original drawing graphs and paths immutable. Keep gaps and riser-symbol
offsets explicit; do not add circle radii as physical pipe lengths.

Old gate identities in the discovery artifact remain candidates until freshly
revalidated against their independent anchors. The new source artifact exposes
two conditional interval candidates per header; it does not publish them or
infer the lower terminal identity by order. Unequal terminal chains remain
unresolved. Whole-axis values, physical lengths, HIL and viewer publication are
separate follow-on stages.
