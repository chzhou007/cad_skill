# Apply existing plan attributes after complete-cohort correspondence

Use this only after the source gate in [complete-cohort support](equivalent-member-source-support.md).
This reuses historical DN and metric readers; it does not establish new local
connections or physical pipe count from duplicate drawing entities.

Run `reconstruct-equivalent-member-plan-attributes` and
`validate-equivalent-member-plan-attributes`. The input manifest binds the new
native source batch, complete prior DN receipt/results, original published
viewer/raw/rendered graphs, and existing specific annotation proof/policy.
Independent validation recomputes the source batch, including the complete
original provider with fresh transitive dependency checks.

The original generic DN receipt may leave a source domain unread even though
a historical F/calibrated provider supports it. Reapply the original native
annotation inventory, explicit calibrated controls, leader barriers, current
T reader and whole-plan inheritance on a separately hashed equivalent-LINE
query view. Native T readers still receive the full original CAD. Remove only
the generic barrier for the exact text resolved by that specific native reader.
Retain all other captions/barriers and every prior explicit conflict. Old known
DN must agree; no values outside the selected source-qualified batch are adopted.

Keep three results separate: qualified correspondence, drawn plan path length,
and complete horizontal T-to-T centreline length. Both native T endpoints and
all paths must be covered. A multi-fragment path needs its original crossover
replay before DN can apply across it; this never measures the omitted span.
Explicit incomplete metadata and unknown inline interiors block a complete
length even when an older generic helper returns a scalar. Installed/net cut
lengths remain unknown. All vertical portions continue to use drawing 11.

Publish with `refresh_cohort_member_attributes.refresh`, followed by
`validate-cohort-member-attribute-viewer`. Append `cohort_member_*` CSV fields;
the seven source-proved generic DN values in the SH16 fixture are declared
changes, while every other prior effective value and historical annotation must
remain exact. Normalize native tuple/point evidence to JSON before comparing
manifest/browser evidence. Changes to effective semantics invalidate prior HIL.
Verify actual Chinese UI and downloaded CSV, including known and conflicting DN,
complete and incomplete lengths, historical column prefix and unrelated rows.

Then run `reconstruct-cohort-member-provider-inventory` and
`validate-cohort-member-provider-inventory`. Inherit every prior provider and
member domain. Add only the new ordinary local-graph intervals and source-proved
ordinary Ts; a cohort observation ID is not a reconstructed physical member.
Known correspondence with unresolved DN/length leaves the matching backlog and
enters its actual attribute task. Do not flatten namespaces to reuse an older
inventory owner that cannot consume this context.

Regression covers missing/competing anchors, ordinary crossings and Z/style
differences in the source owner; DN conflicts and protected specific labels;
fragment gaps and incomplete metric guards; old value/component/annotation
preservation; provider completeness; and technical pass versus pending HIL.
SH16 is the development fixture. LF20 must satisfy the same preconditions
independently; SH16 entity handles and equipment identities are not global rules.
