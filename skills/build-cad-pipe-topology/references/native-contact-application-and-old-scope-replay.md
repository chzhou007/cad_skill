# Adopt native contact owners through each original correspondence domain

After the complete native source-family ownership batch, run
`reconstruct-native-contact-application` and `validate-native-contact-application`.
Pin the complete currently published provider, its immutable Skill snapshot,
parent viewer/graph, corrected source inventory, original qualified source-cohort
configuration, current plan DN result/receipt, display type and the full current
runtime snapshot. The fixed parent worker checks every original runtime asset and
executes the original complete provider owner; a saved receipt alone is insufficient.
Its fixed import domain keeps unrelated callers out of original cache bindings.

First requalify **all affected old scopes**. For equipment branches, reuse the
original native equipment/port, block-chain and current T readers. Both source
routes and their independently mapped T must remain identical. An explicitly
limited plan interface may omit the axis diagram's inline detail: require its
native logical-owner evidence and unknown physical connector status, rather than
comparing an empty plan profile with a full axis branch. An empty profile without
that explicit checked interface domain must fail. Explicitly drawn component
details must still agree. Main/group scopes retain their original scoped profiles
and exact floor namespace; do not reduce a grouped mapping to one edge or mix it
with a reconstructed-member namespace.

Only then batch the existing complete-cohort equipment, native T and bounded-path
readers against the corrected conserved inventory and all prior providers. Reuse
the existing metric, native unit, endpoint and plan DN readers after matching.
Retain explicit DN conflicts and unknown inline/omission lengths. DN or lengths
cannot select a correspondence. Horizontal properties come from the plan;
vertical domains and historical properties remain untouched.

Adopt owner changes and source-recovered components through a versioned rendered
index. Preserve every old symbol path and component ID, equipment membership,
native pipe/node geometry and unknown parameter. Rebuild per-edge inventories.
The graph audit must restore the exact previous rendered graph; its already
qualified attribute bridge remains in the proof chain. Keep historical source
hashes intact and bind the actual new graph hash through an explicit bridge.
Append the new path attribute domain and CSV columns; all old values remain exact
except a declared new previously unknown plan DN. Source copies and annotations
remain as history; semantic confirmations do not carry forward.

Use `refresh_native_contact_application.refresh`, then
`validate-native-contact-viewer`. Check native symbol/schema gates and actual
browser loading, components, pipe properties, both service network CSVs and instance
exports. Finally run `reconstruct-contact-owner-provider-inventory` and its
validator. Inherit all old ordinary/member records, new path/T correspondences,
attributes and the pending frontier. Do not count a source-only or private-profile
candidate as a published correspondence. Preserve unresolved source owners.

scopes (12 logical branches and 17 main observations), one additional source
balancing valve and four new bounded intervals. One interval has direct DN250;
three retain original DN250/300 conflicts. Source lengths and unresolved inline
interiors are evaluated independently. These fixture counts are not global rules.
