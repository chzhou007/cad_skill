# Reapply existing two-arm continuity to current parents and member routes

The native center/rim two-arm algorithm already exists in
`normalize_two_arm_circle_continuity`. This entry extends its current parent
coverage, complete-cohort screening, component reassignment and downstream
member-path adoption; it is not a new circle interpretation.

Use `reconstruct-current-two-arm-routes` and
`validate-current-two-arm-routes` after local equipment, wave and circle repairs.
Replay each applicable current local parent and the complete adopted provider
in its original fixed runtime. Preserve all old source graphs, DN/length
contexts, ordinary/member identities and historical annotations.

Enumerate every current pipe-layer circle. Exactly two unresolved degree-one
endpoints at its center and rim bound a candidate, but do not prove connection.
Run the original native owner: LINE contacts, finite radial extents, same-system
effective colours, XYZ agreement, competing geometry, out-of-plane glyphs,
explicit boundaries and unique original endpoint ownership must all qualify.
Ordinary crossings, third arms, reviewed non-node boundaries and tangent-circle
members retain their respective owners. Existing connected Ts are not repaired
again. Rotations, mirrors and OCS transformations use the original source owner.

Classify source gaps before final node/edge construction. Initial LINE endpoints
are candidates; final ports and edges follow the proved continuity constraints.
Normalize affected chains together, retire only the proved nonphysical endpoints,
reconcile endpoint types and reassign components using explicit edge aliases.
Keep original edge snapshots, drawn fragments and unmeasured marker interiors.
A two-arm corner is a bend or continuation, not a new T; its radius is not a
physical connector length. Recompute dependent ports, component audits, paths,
cross-view mapping and attribute scopes after this topology change.

On a separately hashed plan reading graph, rerun the original external-member
route discovery and native T/path/component readers. Add the exact replayed
two-arm gap owner to its private omission-reading namespace; never enable a
generic near-gap bridge. A previously identified member boundary plus its other
cohort bracket selects the outward half. Require the already mapped remote T
and the original ordered, finite-contact component profiles in both views.
Preserve old canonical bindings for unchanged observations; new observations
explicitly reference the new reading graph and its source edge aliases.

The complete adopted inventory may use sorted JSON while its native producer
uses insertion order. Compare parsed canonical values after native replay,
then retain the actual adopted provider. A serialization-order difference is
not a topology difference. Any changed value still blocks adoption.

`refresh_native_two_arm_routes` exposes only the qualified new correspondence.
Append its CSV fields through `edge-attributes-two-arm.js`, preserving every old
column/value, axis graph, component and annotation. The bounded build can use
the fresh result immediately after the original native verifier; the standalone
viewer verifier replays that owner again. Keep the new plan reading graph and
component inventory in the portable bundle. Verify actual Chinese UI/downloads
and large/local native source Pairs. Mixed paths still take every vertical
segment from drawing 11; connectivity alone assigns no whole-edge DN or length.
