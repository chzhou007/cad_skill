# Source ownership for a complete valve symbol offset from its pipe

Use this fallback only after the original known-family balancing-valve inventory
has been independently replayed. Preserve that complete inventory and consider
only its explicitly unresolved native handles. Recognition still belongs to the
original six-LINE signature reader; do not introduce a second shape classifier.

Run `reconstruct-native-flange-contact-ownership` with fixed source, local graph
and original native inventory bindings, then `validate-native-flange-contact-ownership`.
The new source owner records its implementation hashes, strict readable source
preflight and CSV, and independently recomputes the result during validation.

Read the INSERT's transformed WCS geometry, including rotation, reflection and
negative OCS. Extract the two complete flange strokes using the original
signature's corner relationships. A candidate source pipe must be parallel to
the symbol's port axis and intersect **both actual finite flange strokes at the
same Z**. Neither proximity to the raw INSERT origin nor a widened centre-snap
tolerance proves ownership. A perpendicular crossing, body-only contact, single
flange contact, foreign Z or a line outside the flange footprint does not pass.

Require exactly one native source LINE and exactly one matching current graph
segment, retaining the existing service, source-handle and original-continuity
constraints. Duplicate/coincident source LINEs and competing graph owners remain
unresolved. Do not use a component's layer to change the pipe's supply/return
identity. The contact midpoint locates assignment on the actual pipe; the
original symbol centre and all rendered source geometry remain unchanged. Record
the offset, both source flange segments and intersection fractions. The offset
does not create a physical connector edge or establish an extra pipe length.

Preserve every original component row and unknown parameter. The fallback's new
source inventory is not automatically a published index or an accepted cross-view
mapping. Requalify the affected ordinary or member-scoped component profile using
its existing owner, then adopt through a versioned viewer bridge with exact pipe
attribute preservation and explicit new semantic review identity. Keep prior
annotations as history. If mixed-path profile scope is not proved, leave the
published mapping and viewer unchanged pending that technical check.

Regression includes rotated/mirrored/negative-OCS offsets, actual double contacts,
crossing and single contacts, both Z failures, duplicate lines/graph scopes,
service/source constraints, complete-signature protection and old-row retention.
SH16 14F2D is a source fixture for a roughly 1.66-unit drafting offset; its handle,
offset and graph ID are not recognition rules or generic distance thresholds.
