# Building branch applicability and pipe isolation

Apply the building branch to actual source architectural content in mixed/outdoor/ceiling/support drawings. A pipe system schematic is not automatically an architectural plan. If a generic viewer compatibility adapter executes there, record its mode and zero relevant content separately from meaningful building extraction. Use explicit applicability evidence from layers/native entities, not SH16 sheet numbers.

Source schedules can remain parameter-only. Architectural/maintenance support sheets can deliver context without a pipe graph. Mixed plans can have both building and piping tags. Preserve WCS/source hashes across branches and prepare the display transform from the final pipe graph; do not accept a stale graph transform after pipe normalization.

This owner extracts native context and labels, not pipe ports, T nodes, graph edges or verified room polygons. Pipe normalization never closes a door/opening or repairs a building outline. Explicit valve/instrument layer exclusions precede substring matching of architectural aliases; a door character inside a valve layer name does not prove a door. Unproven categories/translations/rooms stay explicit.

For each task, record applicability, extraction mode, source/code hash, primitive category counts, label/translation state and unsupported/missing representations. Source record counts are not physical wall/room quantities. Unexpected zero context where native plan geometry exists needs investigation; sparse source context must not be filled with fabricated rooms. Support-only context is not evidence for equipment water connections.

Architecture-only changes require graph/node-edge/component/source identity preservation checks. The owning canonical architecture_context.py and the viewer vendor copy must match the dependency engine hash. A documentation revision does not require a fake geometry-engine revision or a vendor resync. If the engine changes, change the owner, deliberately synchronize the portable dependency, then run both owners' relevant source/Pair regressions.

SH16 log example: 05 support context and 06-10 mixed-plan context were re-executed in the all-task refresh; the v1.1.1 architecture algorithm was unchanged. 03/04/11 adapters with zero architectural records did not add building semantics. New workflow requirements do not certify unrecorded historical checks.


Source-scoping handoff: before restricting a building reference, inventory nested MEP/equipment descendants independently of architectural categories. An excluded parent INSERT may contain a whole floor. Exclusion from the architectural sidecar is not exclusion from topology or source-CAD rendering. The pipe branch owns source-backed equipment instances and ports; hand off source chains, native transforms, hashes and disposition of every MEP candidate family. Source comparison must detect a zero-equipment graph against native equipment bodies and block that implementation defect before HIL. Unknown schedule variants and unproved remote ports remain separate from local equipment ownership.
