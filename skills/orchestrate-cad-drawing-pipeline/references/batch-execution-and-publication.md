# 规则批次执行、正式发布和精简状态

批次的单位是一个已证明适用条件的规则族。先在全部适用对象执行，再把残余按源图冲突、缺少个体对应、未给长度、未应用答复分别列出。未知值不填零，未解决边不删除。

## 查找入口

从 `pipeline.py actions` 读取有界结果。`search`/`explain` 从真实 argparse 和历史手工分派语句发现入口；结果包含实现位置、哈希与关联 feature。它帮助定位，不凭命令名猜参数或推断源图适用性。使用目标入口自己的 `--help`。

`current-project --pointer POINTER` 只读取显式项目指针指向的权威文件，并校验其哈希。当前指针可更新，权威历史文件不覆盖。已收到专家答复、已应用规则、已发布值与人工验收是不同状态。

## 执行闭环

`pipeline.py batch` 在一个执行器中调度明确命令数组与依赖阶段。沿用原生任务的核数预算、独立进程、UTF-8日志与输出隔离；几何所有者不因并行改为共享线程执行。

每阶段声明输入、实现、输出和依赖。先生产，再验证，再发布，最后读取正式页面所用属性并核对。上游失败阻止其下游发布，独立图族继续。不能把进程退出0、旧receipt或空报告当成源图与发布通过。

专家答复作为触发输入时使用 [`pipeline.py hil-feedback`](hil-feedback-closed-loop.md)：校验原答复与Pair，按已确认规则群批量调用这些阶段，最终输出应用台账。旧的单独接收回执仍如实表示“已接收”；全闭环的应用完成状态只由本轮原生、验证、回归与发布共同证明。

新配方使用现有生产/发布入口，禁止直接手改最终图或旧证明。SH16示例同时运行完整轴测方向批次和已确认跨图规则生产，再串联正式发布、统一方向属性、编辑器及离线备份修复，核验全部节点边、设备元件、有效值与原始批注。范围由配方声明；该回归不等于从原始DWG重建所有历史阶段。

## 等待与恢复

- `run` 在内部等待阶段进程；`start` 后台启动隐藏进程并返回运行位置。
- `status` 返回有界阶段状态和报告路径；`wait` 按revision等待变化，超时明确无变化，不生成新的成功或阶段revision。
- 原命令完整输出写日志。日常只读状态、差异和失败日志的相关范围，避免把全量JSON、所有源码或全部历史目录灌入上下文。
- 恢复使用新运行目录，旧记录保持原样。只有源输入、实现、依赖与实际输出哈希完全一致的成功阶段可复用，复用与本次原生执行分开记录。
- 产物变化、失败、未完成或依赖变化使相应下游失效。确认状态、未知长度及人工批注规则继续遵守原所有者约定。

### 失败后的显式续接

批次末端失败不自动否定每一个已完成上游，也不能把失败批次改写为成功。若需要采用既有成功阶段作为固定输入，先建立独立来源门槛：核对原始输入、当时执行实现、成功收据与全产物哈希，记录原批次及失败原因；任何受影响产物都不得采用。新配方重新执行受影响阶段和下游测试、验证、发布。

这种来源明确的既有输入不是新一轮冷重建，也不是跨运行缓存命中。不得因此放宽原有缓存条件、宣称未知的历史输入闭合，或改写旧收据。最终报告同时列出原生执行与续接的范围。

已验收的产物目录保持只读。审计程序不得直接导入目录中的Python模块并生成缓存；需要执行或导入时使用隔离副本并禁用字节码写入。即使只新增缓存、业务文件未改，也保留原完整性失败记录并在新目录复核，不能静默删除文件后改判旧批次。

## 正确性与收益

保留全部历史feature ID、源规则和反例。对固定SH16输入，比较全记录身份/连接/元件及正式有效值，不能只对数量。规则变化跑受影响历史/新增测试，发布里程碑运行完整适用回归。

收益同时记录执行器外部调用数、状态返回字节、日志字节、文本token计量及冷/热运行时间；每个数字注明口径。使用通用tokenizer计数仅证明接口文本量，不等于真实模型或账户计费。减少模型等待回合不以跳过原生校验换取。

新执行链、原始输入全链复现、SH16语义正确性、LF20回测及人工验收分别报告；不能因控制器测试通过自动改变工程验收状态。
