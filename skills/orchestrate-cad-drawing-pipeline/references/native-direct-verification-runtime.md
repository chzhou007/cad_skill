# Explicit native-only verification workers

Use this backend only in a new worker process when optional same-batch cache tracking is unnecessary or profiling shows it adds cost without reuse. It is a versioned execution option, not an alternative geometry algorithm or a persisted verification cache.

`native_direct_verification_runtime.install` accepts only the pinned supported `native_replay_session.py` SHA256 and refuses to replace an already imported runtime. It supplies the original library's no-session behavior: every `verify_once` invokes the requested verifier directly, including repeated or changed inputs, and exceptions propagate. It registers no optional cache-read audit hook and never reuses results. The original cache library, historical receipts, native readers and all geometry/attribute checks remain unchanged. Worker reports disclose both library/runtime identities and direct-call counts.

Run `native_direct_worker.py --job JOB_JSON --report REPORT_JSON`. Jobs are data with fixed operations: `verify_lower_parent`, `build_adoption`, `validate_adoption`, `source_gate`, or `build_viewer`. Include `expected_cache_library_sha256`; graph-producing/validating jobs also bind the expected graph SHA256. The pipeline validation operation runs the actual CLI and requires parsed native success with explicit pending/HIL state. Exit 2 alone is insufficient. Any native failure produces a failed report and propagates as a failed process.

Before using a new execution backend for delivery, independently replay a fixed historical native parent and require the exact graph and audit payload hashes. Keep that equivalence report, the original source/runtime hashes, each job and its result alongside new outputs. Never edit historical receipts or mark a prior pending review accepted. Keep existing live work until a replacement has actually passed; any intentional supersession needs explicit evidence and process identity checks, not an observation timeout.

The backend does not promise faster execution: native projection, graph copying and deterministic hashing still execute. Report measured timings per concrete operation; do not call zero cache reuse a speedup. The performance mode does not relax source readability, system separation, topology/attribute scope, source comparison, viewer checks or human acceptance.

When this backend builds a viewer, its input manifest must also bind the actual runtime and worker entry files. `build_visualization.execution_dependency_paths` checks their installed source paths and adds both as hashed manifest dependencies. An unexpected runtime path or a different entry fails before building; legacy builds retain their existing input set. Run `test_native_direct_manifest.py` with runtime, builder and inherited manifest tests.
