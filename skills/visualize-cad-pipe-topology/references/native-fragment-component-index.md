# 局部原生球阀进入查看器及保持旧属性证明

在 topology 的原生局部片段恢复后，使用 `reconstruct-fragment-component-index --manifest M --output NEW` 和 `validate-fragment-component-index --verify-output NEW`。输入固定 parent_manifest、parent_graph、provider、source_inventory 四个 path／sha256。完整当前查看器和局部球阀来源先独立重放；受影响的命名外接管范围复用原 `legacy_named_provider_inventory.replay_floor`，同时核对原始命名端口、源管段、原空隙和供回水。完整平面元件来源须仍与 provider 一致。

当前适用独立命名外接接口及其单边范围。复用原组件 profile 比较；相符者采用，表达差异或未支持范围保留到对照／HIL，不靠新元件数量重配管路。不得把另一楼层的“平面省略”答复无条件推广。源级库存、在线采用、跨图差异分别计数。

复用原实例坐标规范化、符号源几何和原有球阀类型；保留所有旧实例ID／属性、符号、设备、节点、边、路径和旧元件行。恢复函数移除本轮实例及其精确边清单增量后，必须还原完整父图。旧类型不可重复创建。图上的新元件直接引用原始INSERT；未知阻力和长度不填零。

使用 `refresh-fragment-component-viewer --parent P --output NEW --proof PROOF --templates ASSETS/viewer --port PORT`，再独立 `validate-fragment-component-viewer --verify-output NEW`。原 attributeValueContext 逐字段保持，不修改旧 native proof 或旧图哈希。新 componentFragmentOverlay 指向包内固定路径的父图原字节；浏览器先验证新整图及父图哈希，再核对只增了声明的实例／边元件清单，完整还原父图，最后调用原父属性上下文校验。任何管路、旧实例、系统、路径、清单额外变化或父图字节更改都失败。无 overlay 的旧严格校验保持。

运行原生源几何／schema gate、实际浏览器元件检查及供回水CSV；所有旧有效管径／长度及列顺序保持。元件语义变化产生新bundle身份，旧批注保留，人工确认不继承。完整provider继承旧对应、成员和属性待办，仅新增当前元件采用及表达差异清单；后续入口使用该新provider，不把源级1578误报为在线1578。
