# 当前源图冲突统一进入一个工作队列

新增遗留判断时，先盘点独立管径分区页、环路子视图、元件差异页与主工作页。主页面的待答数量不包含独立表单时，不能将其称为全部遗留问题数量。

复用现有完整管径、当前T、三通主管角色、元件原生形状和双法兰归属读取器，批量筛除已修复的旧问题。设备归属变化后的局部图须按原有配置继承入口重读；整张局部图字节相同不需要额外套用设备归属变更的限制。未知、冲突及非物理边界继续保留。

`current_source_review_queue.py` 将通过当前源图范围检查的独立问题合并进标准 `sections/followup_sections`。调用正式入口：

`pipeline.py merge-current-source-review-queue --existing EXISTING.json --proposals PROPOSALS.json --page-root PAGE --output NEW`

每个提案包含一个规范问题ID、原问题SHA、明确的别名、当前源输入及独立核查产物的哈希、原CAD大范围定位和局部Pair。核查产物必须明确仍有冲突、未改图、未赋物理值、未取得人工验收。合并器重新核对文件哈希并调用原 `review_page_preflight`，不根据旧的通过旗标、页面标题或相同数量选择管径。

- 同一管径分区在环路页和全图页的不同视图共用一个规范问题，不重复计数。
- 原题目、原Pair、答复、批注和选项保持。若旧ID的内容或源范围不同，停止覆盖，显式建立新审查版本。
- 旧草稿留在原页面；没有经过题目、源范围和Pair版本核对的草稿不自动继承为确认。主工作页导出必须包含所有当前有效的问题。
- 新问题须有原CAD大图与问题框、局部原CAD／拓扑Pair及具体影响范围；未选表示未答。真实浏览器核对待答数、归档数、图片载入和实际导出字段。
- 实际导出使用 `expert-review-workflow.mjs::buildReviewBackup`，分别保留原始收到的三个答复集和浏览器有效答复快照。旧草稿缺少说明字段时，从原答复补回；明确填写的空字符串或更正保持。不得只核对题目数量，漏掉原中文说明。此过程不改本机草稿、不创建新确认。

此入口只改善源图对照到HIL的接入和完整性，不修改拓扑、元件或属性，不代表冲突已经解决。SH16回归覆盖旧48项答复保留、六组管径分区的重复环路视图去重、元件数量差异与新的表达范围差异的统一待办。
