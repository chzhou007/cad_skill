# Building context, v2.7

For pipeline v1.0 / viewer v2.8, prepare native architectural context through the owning `extract-cad-building-context` v1.1 skill and supply `--building-context architecture.json`. The building CLI accepts either a final display transform or raw graph nodes and applies the neutral projection contract. Viewer rejects source/transform mismatch. Direct legacy builder calls retain auto-detection through a compatibility adapter; manifests label this mode. `scripts/architecture_context.py` in the viewer is a generated, hash-locked portable dependency, not a separately maintained extractor. Synchronize it through the orchestration skill verifier after changing its canonical owner. Set `building_context.enabled` for legacy detection; an explicitly supplied sidecar is always included.

Keep building data in `public/data/architecture.json` and `architecture.svg`, outside graph nodes and edges. Architecture and hydraulic data use the exact same world transform. Preserve source-language labels only in audit data; display English aliases with explicit translation-pending placeholders. Wall/opening categories are source-layer candidates, room labels are not room boundaries, and primitive counts are not physical object counts.

Expose geometry and annotation switches, building fit and room/grid-label location. Building context is visual context, not a selectable hydraulic object. Keep source-CAD comparison and Pair exports aligned. Pair includes local building context even when overlays are off. Its local context JSON preserves original and translated labels; it never includes complete building geometry outside the requested crop.

Gate source hash, coordinate transform, record IDs, unsupported source representations and English-only labels. Require actual browser inspection of the building extent and representative details. Run architecture Python tests and building Pair tests together with existing HIL tests; all source graphs and component counts must remain unchanged. Missing xrefs/proxy graphics and unproved room boundaries remain explicit. Changes do not create human exceptions or Finish Review confirmations.
