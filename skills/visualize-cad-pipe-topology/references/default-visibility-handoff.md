# Default visibility, stage ownership and review handoff

Render the final graph supplied by the pipe owner and the separate architecture sidecar supplied by the building owner. Prefer explicit --building-context in orchestrated runs; compatibility extraction is recorded as an adapter mode, not evidence that every drawing contains architecture. Parameter inputs must be task/source-bound effective artifacts when provided; a reference library alone does not assign a device variant or DN.

Validate node system declarations as well as edge systems. An isolated equipment node can have no edge using its source service. Explicit unresolved/unclassified/pending service must have an English PENDING filter enabled by default. Other named services need explicit configuration; do not hide the node or assign a different service. Retain the loaded graph and source contacts; visibility repair does not create equipment connections or remove resistance requirements.

Default coverage checks need the current all-floors/all-systems/layers state, loaded node IDs versus rendered visible node IDs, native symbol/source coverage and a saved actual-browser observation. A user-disabled layer or selected floor is not recognition failure. Inspect native equipment and components in representative source regions; a correct counter alone does not prove geometry fidelity. Pair crop rendering must include local relevant equipment/components/building geometry independent of browsing overlay switches.

SH16 negative case: 06/07 each had 135 loaded nodes but only 118 default visible nodes. Seventeen pending-service equipment nodes were excluded because the system list was derived only from edges. Existing test_builder.py cases now cover an isolated pending equipment node, an absent typed service configuration and validation of missing node filters. Do not encode 135/118/17 as generic acceptance counts.

Return bundle validation, actual browser/Pair evidence and honest pending limitations to the orchestrator. All applicable task viewers must be regenerated or explicitly accounted for after a shared rendering update. Technical checks never create HIL errors, expert explanations or Finish Review confirmations. An actual issue fix does not auto-close its human record.

Preserve error-only selection/comment entry, scope edits and their review invalidation, independent expert explanations and whole-task confirmation. Source/graph/effective-parameter/building semantics determine review identity; renderer/style versions remain separate. Archive old annotations and avoid migrating confirmations to changed content. Each drawing task has its own review even when shown in a batch dashboard; a calculation projection/aggregate retains its separate identity and known scope.
