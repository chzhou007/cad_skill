# 收到答复后，先消费答复，再重算所属阶段

工作页的浏览器草稿不等于已导入答复。发现已填写的问题时，导出原始备份；用 `pipeline.py receive-current-review-answers --existing cases.js --reply 答复.json --page-root 页面目录 --question-id ID [--question-id ID] --output 新目录` 批量接收。

入口重新核对题目、选项、源证据、Pair 和大范围定位版本；题内答复须与导出的浏览器快照完全一致，中文可读。已有队列源输入须仍匹配其哈希。原答复、说明、题目和图像保持；更正旧答复必须另建明确的更正历史，不能静默覆盖。

产物将答复追加到既有 `received_followup_feedback`，同时保留输入原件和接收记录。题目从“待回答”移到“答复已收”；技术应用和整图人工验收仍未完成。发布前验证实际页面归档与导出，不能只改待办数量。

消费答复时只解除它明确涉及的限制：

- “两图描述同一范围、设备表达简化”可支持该范围的路径级对照；不按接口序号强行匹配不同数量的支路，不据此赋设备身份或未画管长。
- “平面省略、实物按轴测两阀”只解释已核对路径上的元件表达差异。重放原有路径、两端三通、系统、原生元件归属和管径／长度读取器后，才可继续属性应用；保留两图所有原始实例，不制造第二只平面阀的位置、不合并跨图元件。
- 新的连接或属性语义需使相关旧验收失效，旧批注保留为历史。没有明确长度依据的竖段继续留空。
